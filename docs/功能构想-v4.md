# 森林小屋 v4.0 功能构想

> 编制：2026-11-14
> 基线：v3.0.0（四季 × 9 主题 × 5 天气 × 4 居所 + 沉浸/预设/交互/音景/照片/番茄钟/签到/成就/星标/孔明灯/彩蛋/胶囊）
> 原则：不与已实现功能重复；优先"场景里能看见的互动"，坚持零后端

## 评分模型

**综合分 = 价值 V×0.4 + 易实现 E×0.35 + 趣味 F×0.25**（E = 6 − 难度，难度 1=半天内、5=新建子系统）

分组规则：
- **高**：综合 ≥ 3.9 且难度 ≤ 3 —— 本版本可全部落地
- **中**：综合 ≥ 3.6 且难度 ≤ 4 —— 需要排期，或攻坚一项
- **低**：综合 < 3.6，或与现有功能重叠、边际收益弱

## 二、分组依据

1. **高优先级三项都是"把一个已有维度做深"，不是加新维度**：节气深化时间、风铃深化风、观星深化夜。它们都能复用现有系统（season/light/粒子），改动面小、风险低，合计约 8-10 小时。
2. **中优先级里唯一的"高价值高难度"是延时摄影（难度 4）**：它需要补一套"时段光照表"（晨/午/昏/夜 × 四季），会动到 `setLighting` 核心链路，必须单独一轮回归，所以不进"高"。
3. **低优先级的两项各有硬伤**：小动物难度 4 且与"林间访客"主题重叠（先做访客更划算）；TTS 的中文语音在移动端音质不稳定、且与"安静"的产品气质有冲突（可作为无障碍开关而非主打功能）。
4. **未列入的候选**：季节回顾卡、明信片生成器（与拍立得照片墙重叠）、在线人数/弹幕（需后端 + 审核）、DIY 家具摆放（难度 5，等于重做一个项目）——后者已在 v3 规划中说明暂缓，本轮仍不建议。

## 三、建议本版本范围

**做高优先级 3 项 + 中优先级 2 项（篝火故事会、林间访客），约 12-15 小时。**

理由：
- 高优先三项负责"深度"，中优先两项负责"温度"（故事会 + 偶遇），组合起来是"一个更耐逛的版本"，而不是"又多了一堆按钮"。
- 延时摄影虽是本清单里视觉冲击最强的，但它会动光照核心，建议单独放到 v4.1 专门做一轮，避免和大版本混在一起。
- 拍立得照片墙与秋千适合作为 v4.1 的内容补充。

## 四、数据结构草案

```js
// 节气（在 SEASONS 之上叠加一层）
SOLAR_TERMS = [
  { id:'lichun', nm:'立春', season:'spring', phrase:'东风解冻，蛰虫始振', light:{...} },
  ...  // 24 条，每条含季节归属、诗句、微调参数
]
state.term = 'shuangjiang'   // 当前节气；可按真实日期自动推导

// 风铃
windChime = { on:true, amp:0, lastStrike:0 }   // amp 由 weather.wind 驱动

// 观星
STARS_MODE = false
CONSTELLATIONS = [{ id:'beidou', nm:'北斗七星', stars:[[x,y,z],...], lines:[[0,1],[1,2]...] }, ...]

// 故事会
stories = [{ id, lines:['...','...','...'], read:false }]   // 读过标记存 cabin_stories

// 访客
visitor = { nextAt:0, seen:{} }   // seen 记录图鉴
```

## 五、风险与取舍

1. **节气会稀释现有"四季"识别度**：解决方式是节气作为"子标签"，季节仍是主色板（节气只微调 ±5% 的光照与一句诗），不改季节整体观感。
2. **观星模式与自动巡航冲突**：进入观星时需临时接管相机（同沉浸模式），退出时恢复用户视角。
3. **延时摄影会暴露光照插值不平滑**：现有 `setLighting` 是瞬切，加速后可能出现色带跳变，需要引入 lerp 过渡（这也是它被单列的原因）。
