# 森林小屋 v3.0 功能构想（社交化 + 互动机制）

> 设计时间：2026-11-06
> 基线：v2.0.2（四季 × 9 主题 × 5 天气 × 4 居所 + 沉浸/预设/交互/音景/照片/番茄钟）
> 核心约束：**保持纯静态、零构建、零外部依赖**（这是项目最大的分发优势）

## 一、设计原则

1. **社交形态映射，但不建后端**。参照主流平台的机制（打卡 streak、成就徽章、UGC 展示、数字计数、年度报告），用 `localStorage` + URL 参数 + GitHub 公开 API 承载，避免引入服务器与账号体系。
2. **互动必须落在 3D 场景里**，不做纯 DOM 的小工具。每个功能都要有一个可被"看见"的场景载体（灯、火、墙、牌、树）。
3. **访客零门槛**。不登录也能用 90% 的功能；只有"公开留言"需要 GitHub 账号（复用平台能力，不自建）。

## 二、已核验的技术前提

| 前提 | 实测结果 | 影响 |
|---|---|---|
| 匿名读仓库 star 数 | ✅ `api.github.com/repos/{owner}/{repo}` → `stargazers_count` | "收藏数"零后端可实现 |
| 匿名读 Issues | ✅ 返回数组（当前 0 条） | 可用 Issues 作为公开留言板（只读展示） |
| 匿名 API 限流 | **60 次/小时**（当前剩余 58） | 必须缓存到 localStorage（建议 1 小时刷新一次） |
| 写 Issue | 需 GitHub 登录 | 用 `issues/new?title=&body=` 链接跳转，访客用自己账号提交 |

## 三、功能清单（10 项）

评分：**难度 1-5**（1=半天内，5=需要新建子系统）；**优先级 P0-P3**

### P0 — 本版本核心（低成本、高互动、零后端）

| # | 功能 | 定位 | 玩法 / 交互 | 面向场景 | 难度 |
|---|---|---|---|---|---|
| 1 | **签到添柴 · 篝火等级** | 把"每日打卡"变成"把火养着" | 每天首次打开，篝火自动添一根柴；连续 N 天火更旺（火苗高度、光照范围、飞火星数量分 5 档）；断签则回落。所有居所都有对应的"火"（帐篷篝火 / 小屋壁炉 / 房车炉灶 / 树屋吊炉） | 用户把它当每日习惯入口；打开就想看看火还在不在 | **2** |
| 2 | **成就徽章墙** | 参照 GitHub 成就 + 游戏奖杯，给探索行为发奖励 | 触发即解锁：`初次点灯`、`召唤过四种居所`、`集齐六节气`、`听过全部五轨音景`、`连续签到 7 天`、`在雷雨夜停留 10 分钟`。徽章挂在屋内墙上（3D 木框小铜牌），hover 显示解锁条件 | 给"随便看看"的用户一个继续探索的理由；也是分享素材 | **3** |
| 3 | **收藏数 · 实时星标** | 参照 GitHub star / 微博点赞，做社交证明 | 左下角 GitHub 入口旁显示「★ 1」；点开显示完整数字与"已收藏的人"。数据来自 GitHub API，缓存 1 小时，失败静默降级为上次值 | 访客第一眼看到"有人喜欢"，降低陌生感 | **1** |

### P1 — 本版本加分（有记忆点、可分享）

| # | 功能 | 定位 | 玩法 / 交互 | 面向场景 | 难度 |
|---|---|---|---|---|---|
| 4 | **许愿孔明灯** | 参照朋友圈许愿 + 漂流瓶 | 在空地上点「放灯」→ 输入一句愿望（≤30 字）→ 灯笼带着文字缓缓升空、变成星点消失；愿望存本地（最近 3 条可回看）；可一键生成"我的愿望"分享图 | 节日（中秋/七夕/元宵）时的仪式感；情绪出口 | **3** |
| 5 | **季节彩蛋收集** | 参照宝可梦/原神的收集机制 | 每个季节/节日藏 1 个可点击小物（春：笋尖；夏：萤火虫瓶；秋：松果；冬：冰晶；节日各 1 个）。收集后在"收藏册"里点亮，集齐 4 个季节解锁隐藏装饰（门口多一盏走马灯） | 鼓励用户换季节重访，提升留存 | **3** |
| 6 | **时间胶囊** | 参照"给未来写信" | 写一句话 + 选 7/30/100 天后解锁；胶囊埋在树下（3D 小土堆 + 木牌），到期后木牌发光可点开；本地存储，可导出分享码 | 长周期回访钩子，适合学生用户 | **2** |

### P2 — 下一版本（内容量大，但都是零后端）

| # | 功能 | 定位 | 玩法 / 交互 | 面向场景 | 难度 |
|---|---|---|---|---|---|
| 7 | **拍立得照片墙** | 参照 Instagram 九宫格 / 冰箱贴 | 照片模式拍的图自动生成拍立得（白边+日期），钉在屋内墙上；最多 9 张，可删除重排 | 用户记录"我来过的季节"，形成个人时间线 | **3** |
| 8 | **季节回顾报告** | 参照 Spotify Wrapped | 统计本地数据（来过几次、最爱季节、听了多久雨声、放过几盏灯）→ 生成一张长图卡片，可保存分享 | 换季/年末的传播节点 | **3** |
| 9 | **木牌留言墙** | 参照 GitHub Issues 留言板 / 许愿树 | 树上挂木牌，只读展示仓库 Issues 标题（最多 8 条）；点「也写一块」跳转 `issues/new` 用 GitHub 账号提交，回来刷新即出现 | 开源社区互动；让访客留下痕迹 | **4** |

### P3 — 需后端或工程量过大（本版本不做，给出理由）

| # | 功能 | 为什么暂缓 |
|---|---|---|
| 10 | 小屋 DIY 装扮（动森式拖拽摆家具） | 难度 5：需要拖拽拾取、网格吸附、布局序列化、碰撞检测，工作量 ≈ 其他所有功能之和；且与"四居所"系统耦合 |
| 11 | 全站在线人数 / 弹幕 | 必须后端（WebSocket 或轮询接口）+ 审核机制，破坏零依赖；弹幕还涉及内容合规 |
| 12 | 多人在同场景相遇 | 同上，且需要同步协议与状态一致性 |

## 四、更新重点建议

**本版本（v3.0）建议做 P0 三项 + P1 三项，共 6 个功能，预估 14-18 小时。**

理由：

1. **P0 全部满足"零后端 + 难度 ≤3 + 高频回访"**：签到把"看一次"变成"每天来"；徽章给探索理由；星标数提供社交证明。三者合计约 6 小时，却能改变产品的留存结构。
2. **P1 的三个功能都自带"分享物"**：孔明灯产出愿望图、彩蛋产出收集册、时间胶囊产出到期通知——都是可截图传播的素材，符合社交平台的内容逻辑。
3. **P2 的留言墙虽然最"社交"，但依赖 GitHub 账号**，会把非开发者挡在门外，且 Issues 只读展示的体验偏弱，建议等有稳定访客量后再做。
4. **P3 明确不做**：DIY 装扮是"另一个项目"的量级；在线人数/弹幕必须破坏零依赖原则，与项目核心优势冲突。

**若一定要选一个"本版本最值得做的"**：**签到添柴（#1）**。它成本最低（难度 2），但它是唯一能把"随机访问"变成"每日习惯"的机制，且天然复用了已有的篝火/烛光系统。

## 五、数据结构草案

```js
// 签到与篝火等级
streak = { lastDate:'2026-11-06', days:7, level:3 }   // level 由 days 映射 1-5

// 成就
achievements = { firstLight:true, fourDwellings:true, sixFestivals:false, ... }

// 彩蛋收集
collectibles = { spring:false, summer:true, autumn:false, winter:false, midAutumn:true, ... }

// 许愿
wishes = [{ text:'愿家人平安', at:1699..., season:'autumn' }]   // 最多保留 3 条

// 时间胶囊
capsule = { text:'...', createdAt:..., unlockAt:... }

// 照片墙
photos = [{ data:'data:image/jpeg;base64,...', date:'2026-11-06', season:'autumn' }]  // 最多 9 张

// 访问统计（用于年度报告）
stats = { visits:12, bySeason:{autumn:8,...}, rainMinutes:34, wishes:3 }
```

持久化统一走 `localStorage`（键前缀 `cabin_`），并提供「清空本地数据」入口（隐私）。

## 六、与现有系统的关系

| 现有模块 | 被复用的方式 |
|---|---|
| 篝火 / 烛光（`candleLights`） | 签到等级直接驱动 `mul` 与火焰尺寸，无需新建光源 |
| 四居所（`DWELLINGS`） | 每种居所映射一个"火"的载体，签到在任何居所都成立 |
| 季节 / 节日（`THEMES`） | 彩蛋按主题配置藏在对应场景组里，切换主题即可出现 |
| 照片模式（`takePhoto`） | 照片墙直接复用其导出管线，只是把下载改成存进数组 |
| 统计入口（`applyLook` / `setWeather`） | 在此埋点累计"访问次数/听雨时长" |
| GitHub 入口（`#gh`） | 星标数挂在其旁边，共用同一个链接 |

## 七、待确认的取舍

1. **签到是否影响"公平性"**：火势等级只影响视觉，不锁任何功能——建议如此，避免强制打卡。
2. **许愿内容是否公开**：默认仅本地；公开需要后端审核，不建议。
3. **照片墙的存储上限**：base64 照片体积大（每张 300-800KB），9 张可能超 localStorage 5MB 配额 → 需要压缩到 1200px 宽、JPEG 0.8，或改用 IndexedDB。
