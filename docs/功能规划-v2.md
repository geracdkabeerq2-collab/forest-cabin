# 森林小屋 · v2.0 功能规划（头脑风暴 + 评分排序）

> 编制时间：2026-11-06
> 基线版本：v1.1.0（四季 × 9 主题 × 5 天气 × 4 居所，程序化配乐/字幕/巡航/亮度条/URL 分享）
> 参考项目均为此前 GitHub API 核实过的真实仓库（star / license / 活跃度见 `docs/开源调研与MVP方案.md`）

## 评分模型

| 维度 | 说明 | 权重 |
|---|---|---|
| **价值 V** | 对用户体验与传播的提升（1-5） | 40% |
| **易实现 E** | 6 − 难度 D，难度 1=半天内、5=需要重建场景（1-5） | 35% |
| **趣味性 F** | 惊喜感、分享欲、可玩性（1-5） | 25% |

**综合分 = V×0.4 + E×0.35 + F×0.25**（满分 5.0）

分组规则：
- **高**：综合 ≥ 4.0，且难度 ≤ 2 —— 低成本高回报，一个迭代可全清
- **中**：3.5 ≤ 综合 < 4.0，或价值高但难度 ≥ 3 —— 需 2-3 个迭代
- **低**：综合 < 3.5，或收益偏工程/受众窄 —— 视长期规划取舍

## 二、按优先级分组

### 🟢 高优先级（6 项，建议 v2.0 主体范围）

| 功能 | 综合 | 预估工时 | 为什么现在做 |
|---|---|---|---|
| 专注番茄钟 | 4.65 | 4-6h | 场景天然适合"陪伴式专注"，是能把"看一次就走"变成"每天用"的功能；纯前端计时 + 现有音频系统即可 |
| 可交互物件 | 4.25 | 3-4h | 成本极低的"活感"提升：射线拾取已有相机基础，灯/火/灯笼都是现成对象 |
| 沉浸/壁纸模式 | 4.10 | 1-2h | 一个 CSS class 就能把使用场景从"观赏"扩到"常驻背景" |
| 场景预设卡片 | 4.10 | 2-3h | 36 种组合对用户是负担，预设卡片把它们变成"一键选风格" |
| 环境音混音器 | 4.00 | 3-4h | 已有雨/风/雷三轨，补虫鸣/篝火/雪声并做独立音量条即可 |
| 照片模式 | 4.00 | 3-4h | 现有截图只是"存图"，加边框/滤镜/隐藏 UI 后才能当壁纸和社交图 |

**小计：16-23 小时（约 2-3 个工作日）**

### 🟡 中优先级（5 项，v2.1）

| 功能 | 综合 | 预估工时 | 为什么缓一步 |
|---|---|---|---|
| 24h 昼夜循环 | 3.95 | 8-12h | 价值最高但需要重建"时段光照表"（晨/午/昏/夜 × 四季），会牵动现有天气叠加逻辑，需要单独一轮回归 |
| 按真实日期切节日 | 3.95 | 1-2h | 实现极简，但要先定"用户手动改过主题后是否继续覆盖"的规则，和上一项一起做更顺 |
| 小动物 | 3.90 | 6-10h | 建模 + 行为状态机（游走/警觉/逃离）工作量中等，收益是"生机"，适合作为视觉升级主线 |
| 真实时间同步 | 3.65 | 4-6h | 依赖昼夜循环的时段表，应排在其后 |
| 时间胶囊 | 3.60 | 3-4h | 情感向彩蛋，实现简单但需要设计好"提示与召回"的交互，否则容易被遗忘 |

### 🔴 低优先级（6 项，长期或不做）

| 功能 | 综合 | 理由 |
|---|---|---|
| 第一人称漫游 | 3.60 | 价值高但难度 5：需要真实室内建模、碰撞、门交互，等于重做一个项目；当前"凝视型"定位下收益递减 |
| 音乐可视化 | 3.50 | 趣味最高，但需要引入 AnalyserNode + 频谱驱动材质，与现有程序化合成的调度耦合，容易引入抖动 |

| PWA 离线安装 | 3.10 | 已经是纯静态可离线，PWA 主要省一次加载，边际收益低 |

## 三、分组依据（为什么这样切）

1. **"低成本高回报"优先**：高优先级 6 项全部满足"综合 ≥ 4 且难度 ≤ 2"，合计不到 3 个工作日，却能覆盖"陪伴（专注）→ 互动（物件）→ 常驻（壁纸）→ 选择（预设）→ 声音（混音）→ 分享（照片）"六个使用动机。
2. **难度 ≥ 3 的一律不进 v2.0**：昼夜循环与小动物会改动光照/地形核心链路，必须单独一轮做回归，混在大版本里风险不可控。
3. **依赖关系决定顺序**：真实时间同步依赖昼夜时段表 → 排在其后；按真实节日与主题系统耦合 → 与昼夜一起做。
4. **与项目定位冲突的降级**：第一人称漫游虽是同类项目（Mistwood / Forest Game Scene）的标配，但会把"静观"变成"探索"，且成本是其他功能的 3-5 倍，故列低。
5. **零依赖原则不破**：二维码、PWA 框架、音频分析库这类需引入外部包的方案统一降级，避免破坏"单文件 + 本地 three.js + 离线可跑"的核心优势。

## 四、v2.0 建议实施顺序

1. 沉浸/壁纸模式（1-2h）—— 最快见效，也是后续照片模式的基础
2. 场景预设卡片（2-3h）—— 让 36 种组合可用
3. 可交互物件（3-4h）—— 提升"活感"
4. 环境音混音器（3-4h）—— 复用现有音频层
5. 照片模式（3-4h）—— 复用截图 + 壁纸模式的 UI 隐藏
6. 专注番茄钟（4-6h）—— 最后做，因为它要复用前面所有能力（预设、音景、沉浸模式）

**总计 16-23h**，可作为 v2.0.0 一次性发布。
